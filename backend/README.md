# Campus Resource Exchange — Backend (Phase 2)

> **FastAPI + PostgreSQL + SQLAlchemy 2.x + Alembic REST API**

---

## 📌 Overview

The **Campus Resource Exchange Backend** provides robust relational data persistence and REST API endpoints for discovering, filtering, and inspecting campus equipment and laboratory spaces. Built with Python, FastAPI, SQLAlchemy 2.x, and PostgreSQL, it enforces relational integrity across resources, categories, physical campus locations, and departmental custodians.

> [!NOTE]
> All sample resources, laboratory contacts, and departmental inventories generated by seeds and migrations are **entirely fictional** and provided solely for local prototyping and testing.

---

## 🛠️ Technology Stack

- **Framework:** [FastAPI](https://fastapi.tiangolo.com/) (v0.115+)
- **ASGI Server:** [Uvicorn](https://www.uvicorn.org/) (v0.30+)
- **Database:** [PostgreSQL](https://www.postgresql.org/) (relational engine)
- **ORM:** [SQLAlchemy 2.x](https://docs.sqlalchemy.org/en/20/)
- **Driver:** [psycopg v3 (binary)](https://www.psycopg.org/psycopg3/)
- **Configuration & Validation:** [Pydantic v2](https://docs.pydantic.dev/) + [pydantic-settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/)
- **Database Migrations:** [Alembic](https://alembic.sqlalchemy.org/en/latest/)
- **Automated Testing:** [pytest](https://docs.pytest.org/) + [HTTPX](https://www.python-httpx.org/)

## 🚀 Local Setup & Installation

### 1. Create and Activate Virtual Environment

From the project root:
```bash
# Windows (PowerShell)
python -m venv backend/.venv
backend\.venv\Scripts\Activate.ps1

# Linux / macOS
python3 -m venv backend/.venv
source backend/.venv/bin/activate
```

### 2. Install Dependencies
```bash
pip install -r backend/requirements.txt
```

### 3. Configure Environment Variables

Copy the template:
```bash
cp backend/.env.example backend/.env
```

Edit `backend/.env` with your PostgreSQL credentials:
```ini
ENVIRONMENT=development
DEBUG=True
DATABASE_URL=postgresql+psycopg://<username>:<password>@localhost:5432/<dbname>
CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,http://localhost:5173,http://127.0.0.1:5173
```

## 🗄️ Database Setup, Migrations & Seeding

### 1. Create PostgreSQL Database
In `psql` or pgAdmin:
```sql
CREATE DATABASE campus_resources;
```

### 2. Apply Database Migrations
Run Alembic from the project root or inside `backend`:
```bash
# From project root:
& "backend/.venv/Scripts/alembic.exe" -c backend/alembic.ini upgrade head

# Or from inside /backend:
cd backend
alembic upgrade head
```

### 3. Seed Fictional Campus Resources
The seed script is safe and repeatable. It will not duplicate records on successive executions:
```bash
# From project root:
& "backend/.venv/Scripts/python.exe" -m app.seed

# Or with activated venv inside /backend:
cd backend
python -m app.seed
```

## 📡 REST API Endpoints

### 1. `GET /api/v1/resources`
Returns a paginated list of resources matching combined filter criteria.

**Query Parameters:**
- `search` *(string, optional)*: Case-insensitive search on name, model, description, department, or building.
- `category` *(string, optional)*: Filter by category name (e.g. `Laboratory Equipment`) or category ID.
- `availability` *(string, optional)*: Status filter: `available`, `in_use`, or `maintenance`.
- `building` *(string, optional)*: Campus building name (e.g. `Turing Engineering Hall`).
- `sort_by` *(string, default: `name`)*: `name`, `category`, `availability`, or `created_at`.
- `sort_order` *(string, default: `asc`)*: `asc` or `desc`.
- `page` *(int, default: 1)*: 1-indexed page number.
- `page_size` *(int, default: 12, max: 100)*: Items per page.

**Response Structure:**

### 2. `GET /api/v1/resources/summary`
Calculates live dashboard metrics from database records.

**Response:**
```json
{
  "total_resources": 12,
  "available_now": 9,
  "category_count": 5,
  "requires_verification": 6
}
```

### 3. `GET /api/v1/resources/{id}`
Returns full relational details for an individual resource. Returns `404 Not Found` if the identifier is unknown.

## 🔧 Troubleshooting

1. **`OperationalError: connection to server failed`**
   - Ensure PostgreSQL service is started: `Get-Service *postgres*` (Windows) or `sudo systemctl status postgresql` (Linux).
   - Verify `DATABASE_URL` username, password, host, and port in `backend/.env`.
2. **CORS Errors in Browser Console**
   - Verify that your frontend origin (e.g. `http://localhost:3000`) is included in `CORS_ORIGINS` in `backend/.env`.
3. **ModuleNotFoundError when running seed or app**
   - Ensure you run using the virtual environment python or specify `--app-dir backend`.
