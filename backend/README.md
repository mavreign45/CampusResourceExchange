# Campus Resource Exchange — Backend (Phase 3)

> **FastAPI + PostgreSQL + SQLAlchemy 2.x + Alembic + JWT Auth & RBAC**

---

## 📌 Overview

The **Campus Resource Exchange Backend** provides relational data persistence, JWT authentication, Role-Based Access Control (RBAC), training eligibility verifications, and REST API endpoints for discovering and managing campus equipment and laboratory spaces.

The platform enforces trusted access governance: high-precision equipment requires verified safety credentials before access requests can proceed.

> [!NOTE]
> All sample resources, laboratory contacts, and departmental inventories generated by seeds and migrations are **entirely fictional** and provided solely for local prototyping and testing.

---

## 🛠️ Technology Stack

- **Framework:** [FastAPI](https://fastapi.tiangolo.com/) (v0.115+)
- **ASGI Server:** [Uvicorn](https://www.uvicorn.org/) (v0.30+)
- **Database:** [PostgreSQL](https://www.postgresql.org/) (relational engine)
- **ORM:** [SQLAlchemy 2.x](https://docs.sqlalchemy.org/en/20/)
- **Driver:** [psycopg v3 (binary)](https://www.psycopg.org/psycopg3/)
- **Security & Cryptography:** [bcrypt](https://pypi.org/project/bcrypt/) (salt + hashing) + [PyJWT](https://pyjwt.readthedocs.io/) (JWT tokens)
- **Validation:** [Pydantic v2](https://docs.pydantic.dev/) + [email-validator](https://pypi.org/project/email-validator/) + [pydantic-settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/)
- **Database Migrations:** [Alembic](https://alembic.sqlalchemy.org/en/latest/)
- **Automated Testing:** [pytest](https://docs.pytest.org/) (34 unit and integration tests)

## 👥 Role-Based Access Control (RBAC)

The system supports four distinct roles:

1. **Student (`Student`):**
   - Public registration strictly assigns this role.
   - Can discover resources, submit training clearance requests, and view their own verified credentials.
   - Cannot approve or review requests or manage users.

2. **Faculty Researcher (`Faculty Researcher`):**
   - Can discover resources, submit advanced lab clearance requests, and view their own credentials.
   - Assigned by university administration.

3. **Lab Custodian (`Lab Custodian`):**
   - Authorized lab supervisor or equipment manager.
   - Can inspect pending verification requests from students in the review queue.
   - Can approve or reject requests with audit notes.
   - Conflict-of-interest safeguard: cannot approve their own requests.

4. **Administrator (`Admin`):**
   - Full institutional oversight.
   - Can review all verification requests across campus.
   - Can manage user roles (promote students to Lab Custodian or Admin).
   - Bootstrapped safely via environment variables.

## ⚙️ Configuration & Environment

Create a `backend/.env` file from `backend/.env.example`:

```ini
DATABASE_URL=postgresql+psycopg://postgres:postgres@localhost:5432/campus_resource_exchange
API_V1_STR=/api/v1
PROJECT_NAME="Campus Resource Exchange API"
DEBUG=true
CORS_ORIGINS=["http://localhost:3000","http://127.0.0.1:3000"]

# Authentication & Security
JWT_SECRET_KEY=cre_development_secret_key_change_in_production_12345
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=1440

# Optional Initial Admin Bootstrap
ADMIN_BOOTSTRAP_EMAIL=admin@university.edu
ADMIN_BOOTSTRAP_PASSWORD=AdminSecurePassword2026!
ADMIN_BOOTSTRAP_NAME="Campus Administrator"
```

## 🚀 Setup & Execution

### 1. Activate Environment and Install
```bash
# Windows
backend\.venv\Scripts\Activate.ps1
pip install -r backend/requirements.txt
```

### 2. Apply Migrations
```bash
cd backend
alembic upgrade head
```

### 3. Seed Database & Bootstrap Admin
```bash
python -m app.seed
```

### 4. Start Server (from project root)
```bash
# If running from project root in PowerShell:
uvicorn app.main:app --app-dir backend --reload --port 8000
# OR:
uvicorn backend.app.main:app --reload --port 8000
# OR without environment activation:
& "backend\.venv\Scripts\python.exe" -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

Interactive API documentation will be available at:
- **Swagger UI:** `http://localhost:8000/docs`
- **ReDoc:** `http://localhost:8000/redoc`

## 📡 API Endpoints Reference

### 🔐 Authentication (`/api/v1/auth`)
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/api/v1/auth/register` | Public | Register new student account (always assigns `Student` role) |
| `POST` | `/api/v1/auth/login` | Public | Authenticate with email and password, returns JWT token |
| `GET` | `/api/v1/auth/me` | Authenticated | Fetch authenticated user profile |
| `POST` | `/api/v1/auth/logout` | Authenticated | Invalidate session |
| `GET` | `/api/v1/auth/users` | Admin only | List campus users with filtering by role |
| `PATCH` | `/api/v1/auth/users/{id}/role` | Admin only | Update user role (`Student`, `Custodian`, etc.) |

### 🛡️ Eligibility & Verification (`/api/v1/eligibility`)
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/eligibility/requirements` | Public | List standard campus training requirements |
| `GET` | `/api/v1/eligibility/me` | Authenticated | List current user's clearances and request history |
| `POST` | `/api/v1/eligibility/requests` | Authenticated | Submit clearance application (enters `Pending Review`) |
| `GET` | `/api/v1/eligibility/requests` | Custodian / Admin | Reviewer queue (filter by status, requirement type) |
| `PATCH` | `/api/v1/eligibility/requests/{id}/review` | Custodian / Admin | Approve (`Verified`) or reject (`Rejected`) with audit notes |

### 📦 Resources (`/api/v1/resources`)
| Method | Endpoint | Access | Description |
|---|---|---|---|
| `GET` | `/api/v1/resources` | Public | Filtered, sorted, paginated resource catalog |
| `GET` | `/api/v1/resources/summary` | Public | Live count of total, available, and verified assets |
| `GET` | `/api/v1/resources/{id}` | Public | Detailed resource specifications and location |

## 🧪 Automated Testing

Run the full pytest suite:
```bash
& "backend/.venv/Scripts/python.exe" -m pytest backend/tests -v
```

All 34 tests run in an isolated in-memory SQLite database:
- `test_auth.py`: 12 tests (registration, role assignment safety, hashing, JWT expiration, admin RBAC)
- `test_eligibility.py`: 9 tests (clearance submission, reviewer queue, conflict of interest checks)
- `test_resources.py`: 13 tests (search, category, status, building filters, sorting, pagination)
